# Release checklist

- Review tracked files, staged archives, and full public Git history for private identifiers and real deployment paths.
- Keep the memory project separate from unrelated desktop applications.
- Run offline tests, syntax checks, SDK/installation checks appropriate to changes, and privacy scanning on the exact candidate.
- Record precise validation scope; distinguish reused engine evidence from newly measured renamed fixtures.
- Verify archive file sets and SHA-256 values; publish no private databases, access files, or experiment homes.
- Publish only with current explicit authorization, and verify public source, release assets, and CI afterward.
